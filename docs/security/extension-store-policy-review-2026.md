# The Ludy extension against the Chrome Web Store policy of 2026 (D1)

Issue #3180 (step D1 of [Meetings integrations](../plan/meetings-integrations.md), section 7), reviewed on 2026-11-15 at commit `c483edbc` of `main` and updated on 2026-11-27 for #5224 (owner decision #1210: Ludy Cloud lock and split `app.ludy.vn` / `api.ludy.vn` origins). Scope: the extension (`apps/extension/**`), its store assets (`apps/extension/store/**`), the listing and privacy answers drafted in [the extension store runbook](../runbooks/extension-store.md), and the privacy page `https://ludy.so/privacy` (`apps/web/src/content/privacy-*.ts`). It is useful for D2 (Edge) and for the owner's submission (#2584); the things only a person can do are in the runbook, section "Policy review 2026: what only a person can do".

## What could and could not be read

**The store's own policy pages could not be read.** The session that wrote this review has no network route to `developer.chrome.com` (the name does not resolve: it is outside the session's allowed domains), so the program policies, the user data policy, the Limited Use text and the blog post on the 2026 changes were **not read**. No other route was tried (no mirror, no search-engine summary, no cached copy): a policy read second-hand is not evidence. To read them, `developer.chrome.com` has to be allowed in the session's network settings, or a person reads the pages (runbook, item P1).

What this review rests on instead:

- **The requirement as recorded in the issue and the plan** (research of 2026-11-14, not re-read here): the policy in force from 2026-08-01 requires the data an extension collects to be necessary for one disclosed purpose, every collection to be prominently disclosed, and the most common refusal is a permission that is asked and not used; the review points the issue lists (single purpose, permissions asked versus used, prominent disclosure before the first recording, the privacy policy saying where audio is processed and for how long, the data-safety answers, no remote code, limited use).
- **General knowledge of the long-standing store policies**, from before this session and **unchecked against the current text**: that is why each verdict below is "the extension against the requirement as summarized", and why every store-side wording is a person's item to confirm.
- **The code and the texts of this repository**, which were read: each piece of evidence below is a file and line of the repository.

A verdict here is therefore a statement about the extension. It is not a statement that the store will accept it.

## The points, with verdict and evidence

| # | Policy point | Verdict | Evidence |
|---|---|---|---|
| 1 | Single purpose | **Pass, wording fixed** | One purpose: capture work from the member's active browser tab into their own Ludy Cloud workspace (primarily browser meeting audio + mic after explicit consent, plus optional Notes Quick Capture / click-only Web Clipper; `manifest.json` description, `_locales/*/messages.json`). The shell controls serve this purpose: sign-in (`popup.ts` / `signin.ts`), org picker, "starting soon" calendar card (`agenda.ts`, B2), live notes (`capture-run.ts`, ticked per meeting), and opt-in Quick Capture / Web Clipper (`page-capture.ts`). |
| 2 | Permissions asked and used | **Pass** (one item for a person) | `storage`: `popup.ts`, `background.ts`, `state.ts`. `identity`: `popup.ts` (`launchWebAuthFlow` fallback when the sign-in tab cannot open). Host `https://api.ludy.vn/*`: every network/RPC/token request goes through `createClient(apiAddress, token)` (`api.ts`); there is no other `fetch`. `optional_host_permissions`: **removed completely** in #5224 (2026-11-27 owner decision A1: Chrome Web Store package locks strictly to Ludy Cloud; `manifest-policy.ts` forbids `optional_host_permissions`). `web_accessible_resources`: pinned solely to `connected.html` for `https://app.ludy.vn/*` (`manifest.json`, `manifest-policy.ts`). Optional permissions: `tabCapture` + `offscreen` (asked on click when enabling Meetings, released when disabled), `activeTab` (asked on enabling Meetings or Web Clipper, released when both are off), `scripting` (asked solely on enabling Web Clipper, released when off). No permission is asked and unused. CI fails any manifest violating `src/manifest-policy.ts` (`scripts/check-manifest.mjs`). **For a person:** confirm on real Chrome that `offscreen` together with `tabCapture` is accepted as optional permissions (README manual test step 3). |
| 3 | Prominent disclosure before the first recording | **Pass** | Before turning meeting recording on, `meetingsNote` (`strings.ts`) states that the active tab + mic are recorded and uploaded to Ludy on stop. Inside the recording card, consent notice + method selector + confirmation checkbox gate `#start` (`consent.ts`, `popup.ts`). Live notes (`liveNotesHint`) and calendar shortcut (`agendaNote`) disclose collection at the point of choice. The device name (browser and operating system) sent when connecting is disclosed on the `/-/extension/connect` web consent page (`apps/app/src/routes/extension-connect.tsx`) before member approval and in the privacy page/runbook (`#sign-in-device-note` removed from the compact 340px popup in #5224). |
| 4 | Privacy policy: where audio is processed and for how long | **Pass** (lawyer must re-read) | The page exists at `/privacy` and `/en/privacy` and has the extension first: what is handled, the consent step, Ludy Cloud processing, storage and encryption, who reads, the transcription provider and AI-off case, retention table (audio 30 days by default, video 7, text 12 months), rights, plus calendar reading, live notes, `activeTab` duplicate-call detection, and click-only Web Clipper disclosures. |
| 5 | Data-safety answers of the listing (the "Privacy practices" tab) | **Pass** (a person enters them) | The runbook's declaration (Authentication information, Personal communications, Personally identifiable information, Website content: Yes; History, location, financial, health, user activity: No; the three certifications) matches the current code. The form is a declaration: the owner enters it and the lawyer (#2585) sees it first. |
| 6 | No remote code | **Pass** | Manifest V3; `content_security_policy.extension_pages` is `script-src 'self'; object-src 'self'` and `manifestViolations` refuses `unsafe-eval`, `unsafe-inline`, any address or `*` there; `content_scripts`, `externally_connectable`, `optional_host_permissions`, `update_url`, `declarative_net_request` and `sandbox` are refused (`manifest-policy.ts`); `web_accessible_resources` allows `connected.html` for `https://app.ludy.vn/*` only; `src/` and `scripts/build.mjs` have no `eval`, `new Function`, `importScripts`, `document.write`, remote script imports, or `innerHTML` assignments; the build runs no bundler and the package has no third-party runtime dependency (`@ludy/meeting-recorder` is copied into `dist/shared/`). |
| 7 | Limited use and handling of user data | **Pass on behavior; wording for a person** | Behavior: recordings, tokens, notes/clips, and the calendar list go only to `https://api.ludy.vn` (and, when `STORAGE=s3`, the single presigned upload URL granted by the server); no analytics, telemetry, or advertising identifier; nothing is sold, used for advertising, or used for credit. The extension token is scoped to one org, one member, and approved scopes, expires after 90 days, and is revocable in Ludy. **Not verifiable here:** whether the policy asks for a specific affirmative "Limited Use" sentence in the privacy policy or listing (runbook item P4). |
| 8 | Listing text matches what the extension does (no misleading metadata) | **Updated for #5224** | The runbook's single-purpose statement, long descriptions, permission justifications (`https://api.ludy.vn/*` + no `optional_host_permissions`), and `scripts/store-art.mjs` copy match the Ludy Cloud-locked store package. Store PNG assets in `apps/extension/store/` are scheduled for regeneration via `node scripts/store-art.mjs` in a follow-up screenshot step. |
