# YouTube comments: live check

Settles, on one real YouTube channel the owner controls, the YouTube Data API facts that the comment adapter of the conversation core (issue [#3134](https://github.com/DOS/Ludy/issues/3134), [plan](../plan/conversations-channels.md) section 4.5, [ADR-0041](../adr/0041-conversation-core.md)) relies on. **No official page was read when the adapter was built** (the build session's network denied `developers.google.com`), so every field name, call shape and unit cost below is tagged **[O]** (an official page was among the plan's search results, not opened), **[M]** (recalled, not seen) or **[U]** (not found) in the plan, and none is a rule of the software until a row here is filled with what the platform answered. Until then the adapter is built against recorded answers of those shapes and a wrong shape fails closed (a comment that cannot be read is dropped, a call the platform refuses is typed and shown), never open.

Markers: **[PERSON]** only a person can do it (the owner: the Google Cloud console, the YouTube channel, a second Google account for test comments). **[AGENT]** a Ludy session can do it with the owner's go-ahead. Never paste a secret, a token, a client id or a viewer's comment into chat, an issue or a commit: write what each step showed ("matched", "no match", the error reason, the HTTP status, the units).

**Nothing here costs Ludy money.** The YouTube Data API is free inside its quota; an extension is a request to Google (time, no fee found [U]).

## 0. What the owner sets up

**[PERSON]** in the Google Cloud console, on the project that `CHANNEL_GOOGLE_CLIENT_ID` and `CHANNEL_GOOGLE_CLIENT_SECRET` name (see [social-live-check.md](social-live-check.md)):

1. **The API and the scope.** The YouTube Data API v3 is on; the consent screen lists `https://www.googleapis.com/auth/youtube.force-ssl` (the connect dialog already asks for it since #791, for first comments, playlists and edits). Ask whether Google's **verification** is needed for a sensitive scope before accounts that are not test users can connect [U]; write the answer in row 1. If it is needed it is an owner action and costs Ludy no money.
2. **The quota page** (IAM and admin, Quotas, YouTube Data API v3): note the day's limit (10,000 units by default [O]) and the units already used, so rows 4 and 5 can be read against it.
3. **A second Google account** to write test comments, and one **public video** on the connected channel to comment under.
4. **The deployment's settings:** `CHANNEL_GOOGLE_CLIENT_ID`, `CHANNEL_GOOGLE_CLIENT_SECRET`; `CHANNEL_YOUTUBE_HISTORY=true` (the default) for the poll.

## 2. Steps

1. **Switch it on (rows 1, 9).** **[PERSON]** in Ludy, `Social > Channels`, under the YouTube channel: tick **Đọc và trả lời cả bình luận dưới video của kênh này** (owner or admin only). If the box is disabled with the hint to reconnect, reconnect the channel with the comment permission ticked. **[AGENT]** reads the connection's `comments_enabled` and scopes and confirms the switch is on and `youtube.force-ssl` is among the scopes.
2. **Inbound comment by poll (rows 2, 4, 6, 10, 11).** **[PERSON]** with the second account, comment on a video of the channel. **[AGENT]** reads the quota page's units, waits for the next poll (the Channels screen shows "Next reading"; turn the switch off and on to read at once), and reads them again: the difference is row 4. The comment is in `Social > Inbox` and under the video's **Bình luận** tab, one thread, one unread mark, with the viewer's name.
3. **A reply to an older comment (row 3).** **[PERSON]** reply, with the second account, to a comment written more than a day ago. **[AGENT]** reports whether the next poll brought it.
4. **Answer (rows 5, 6, 10).** **[PERSON]** answer the thread from Hộp thư, press Send. Confirm it appears under the viewer's comment on YouTube as the channel, the message ends `sent`, the poll after it adds no second message, and a text of 8,001 characters is refused by Ludy before any call. **[AGENT]** reads the quota page's units before and after (row 5) and the screen's "replies used" figure.
5. **Interval (row 7).** **[AGENT]** records the "Next reading" times over a few hours with no new comment (the gaps grow to 120 minutes), then **[PERSON]** comments and the next gap is 15 minutes; **[AGENT]** compares the screen's "used" figure with the quota page at the end of the day.
6. **Quota spent (row 8).** Only on a test project with a lowered quota, or skipped with the row saying so. **[AGENT]** confirms the screen's message, that a Send is refused with the reset time and no call is made, and that polling and sending resume after the reset.
7. **Dy (AI part).** **[PERSON]** with the AI budget on, open a new comment thread: a draft appears for a person to read, edit and send (metered, `auto_draft` for the automatic ones), saved replies and `{tên}` work, an intent label is suggested. Nothing is sent until the person presses Send. With the AI off the thread still opens and can be answered.
8. **Refusals (row 12).** **[PERSON]** try a reply under a video with comments off and under a comment the viewer deleted; **[AGENT]** reads the message each showed.

## 3. What is not built (and why)

- **Push:** no comment push was found [U]; the channel is polled. A push service for new uploads exists and does not help here.
- **Hide or reject a comment:** `canHide` is false in v1. Moderation acts on someone else's words; it is a second step after row 13.
- **A new top-level comment on a video** (`commentThreads.insert`): out of v1. Ludy answers viewers; posting is Social's first-comment feature.
- **Replies to a reply of someone else's, likes, pinning, the creator heart and the live chat:** not read or written.
- **A shared quota across channels:** the quota is per Google project, so one noisy channel can spend what the others need. Each connection has its own polling budget (150 units a day) to bound that, and Ludy Cloud needs a quota extension from Google before many channels connect (an owner action: time, no fee found [U]); the Channels screen shows only what Ludy counted for the connection, not the project's total, which is on the Cloud console's quota page.
