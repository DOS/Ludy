## 1. Foundations already at a high bar (do not rebuild)

1. **Single write path and database-enforced multi-tenancy:** Every state mutation runs through `Runtime.execute()` (`packages/kernel-runtime/src/runtime.ts`), entering a tenant context checked by `RESTRICTIVE` RLS (`crove_kernel.apply_tenant_rls`), composite keys `(org_id, id)`, pinned `search_path = pg_catalog, pg_temp` on every SQL function, non-owning login roles, and an automated cross-org RLS and `EXECUTE` matrix (`apps/kernel/test/invariant/rls-matrix.db.test.ts`).
2. **Isolated document and media sandboxes (`crove-extract` and `crove-media`):** The kernel image holds zero PDF, XML, MIME, native or WebAssembly parsers, verified by planted-fault CI controls (`.github/workflows/ci.yml:478-515`). Parsing runs in short-lived Node 26 `--permission` child processes with an RSS memory watchdog (`apps/extract/src/sandbox.ts`), and `seal.ts` (`apps/extract/src/seal.ts:82-116`) rejects PDF JavaScript, Launch, XFA, OpenAction and oversized object graphs inside the network-isolated container (`internal: true`, `read_only: true`, `cap_drop: ALL`).
3. **SSRF, XSS, public-route enumeration and DB-backed eSign abuse limits:** `egressFetch` (`packages/kernel-runtime/src/egress.ts`) resolves DNS once, blocks private/link-local/NAT64/metadata ranges across all answers, and pins the socket to the verified IP to defeat DNS rebinding. The SPA enforces `require-trusted-types-for 'script'` (`apps/app/vite-csp.ts`, `apps/app/vercel.json`) with a static test forbidding unsafe DOM sinks (`apps/app/test/trusted-types.test.ts`). `apps/kernel/test/invariant/route-coverage.test.ts` enumerates every Hono route and fails when an unlisted route skips `authenticate()`. Public eSign and direct-signing links enforce DB-backed hourly OTP and start budgets plus 5-attempt lockouts (`supabase/migrations/20270105040000_crove_sign_orgless_resolver.sql:1077`, `20270115170000_crove_sign_direct_link_public.sql:1962`).
4. **Deterministic AI guardrails and metering:** All **50** registered model features pass through `metered()` (`packages/agent/src/meter.ts:20-120`, enforced statically by `meter-coverage.test.ts`), pseudonymize HR/payroll identities with aliases (`C1`, `E1`) while blocking PII leaks (`PayrollPromptLeakError`; recruiting briefs pass wage-band status rather than raw salaries), reject ungrounded numbers (`statedFiguresProblem`), and persist AI outputs as `tainted: true` until human confirmation.

### SEC-03 (`P1`, `line:platform`) - Make `minimumReleaseAge` explicit and strict in `pnpm-workspace.yaml`

- **Evidence:** `pnpm-workspace.yaml:73-105` lists 31 `minimumReleaseAgeExclude` entries (covering 32 package-version pairs) and `renovate.json:9` sets `"minimumReleaseAge": "1 day"`. While `pnpm@12.11.2` defaults `minimumReleaseAge` to `1440` minutes internally, `minimumReleaseAgeStrict` defaults to `false` (allowing fallback when an exact pinned catalog version has no older match unless strict mode is enabled), and relying on implicit package-manager defaults hides policy intent.
- **Recommendation:** Declare `minimumReleaseAge: 1440` and `minimumReleaseAgeStrict: true` explicitly in `pnpm-workspace.yaml`, and prune `minimumReleaseAgeExclude` entries whose pinned versions have aged past 24 hours.

### SEC-05 (`P2` single-host, `P1` before multi-replica API - `line:platform`) - Cross-replica state for OAuth registration and MCP grant concurrency/rate limits

- **Evidence:** Public eSign endpoints already enforce cross-replica hourly OTP and direct-start limits in PostgreSQL (`20270105040000_crove_sign_orgless_resolver.sql:1077`, `20270115170000_crove_sign_direct_link_public.sql:1962`), using in-memory `RateLimiter` buckets only as an outer per-minute L7 shield. By contrast, RFC 7591 dynamic client registration (`registerLimiter` and `registerGlobalLimiter` in `apps/kernel/src/mcp-endpoint.ts:112-113`) and MCP per-grant request rate and active concurrency (`grantLimiter` and `inFlight` in `apps/kernel/src/mcp-endpoint.ts:198-203`) exist **only** in per-process memory (`mcp_rows_charge` in PostgreSQL caps daily read rows, not write/proposal calls or concurrency). Across `N` API replicas or across restarts, those limits multiply by `N` or reset.
- **Recommendation:** Before running multiple API replicas, back `/oauth/register` global/IP caps and per-grant MCP concurrency/short-window budgets in PostgreSQL (modeled on `createDbEmailLimiter` in `apps/kernel/src/auth-email-limit.ts`), keeping in-memory `RateLimiter` in front to shed unauthenticated floods before DB I/O.

### SEC-06 (`P2`, `line:platform`, `line:frontend`, `line:meetings`) - Container, `crove-media`, `apps/web`, WORM and extension defense in depth

1. **Kernel `Dockerfile` copied-tree ownership and inspector flag (`Dockerfile:39-40,51`):** Both `COPY --from=kernel --chown=node:node /app /app` and `COPY --from=web --chown=node:node /app/apps/app/dist /app/apps/app/dist` make the copied application code and static bundle writable by the `node` runtime user (whereas `apps/extract/Dockerfile:24` and `apps/media/Dockerfile:33` keep copied code owned by `root:root`), and `ENTRYPOINT` at line 51 omits `--disable-sigusr1`. Drop `--chown=node:node` on both `COPY` lines (retaining `node:node` on `/data/*` at line 41) and add `--disable-sigusr1` (verifying `ci.yml`'s `kernel-image` planted-fault tests, which already plant as `--user 0`).
2. **Compose service hardening and DB network scoping (`docker-compose.yml`, `tools/deploy/compose.pilot.yml`):** Add `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, and `pids_limit` on `crove`, `api`, `worker`, `prober`, and `auth`. Place `db` on an `internal: true` network shared by the DB-consuming services (`migrate`, `auth`, `auth-grants`, `crove`/`api`, `worker`, `prober`, `usage`), while keeping external egress networks only on services that talk to external endpoints (`api`, `worker`, `prober`, `auth` for SMTP).
3. **`crove-media` per-child RSS watchdog and queue-wait timeout (`apps/media/src/ffmpeg.ts:101-135`, `apps/media/src/server.ts:346,390`):** Add a `/proc/<pid>/status` RSS watchdog around `ffmpeg`/`ffprobe` child processes (matching `apps/extract/src/sandbox.ts:112-120`) so a pathological stream under `MEDIA_CONCURRENCY > 1` fails cleanly without an container-wide OOM kill. 4. **Marketing site HTTP security headers (`apps/web/next.config.mjs`, `apps/web/src/proxy.ts`):** Add `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, and `Permissions-Policy` to `apps/web`, asserted in the `web` CI job (`.github/workflows/ci.yml:255`).
5. **Dedicated least-privilege WORM S3 credentials and `pilot-check` (`apps/kernel/src/worm.ts:73`, `docs/runbooks/worm-archive.md:70`, `apps/kernel/src/pilot-check.ts:450-479`):** The worker's WORM archiver and nightly verifier require `s3:PutObject`, `s3:PutObjectRetention`, `s3:GetObject`, `s3:ListBucket`, `s3:ListBucketVersions`, and `s3:GetBucketObjectLockConfiguration` (never `s3:DeleteObject` or `s3:BypassGovernanceRetention`). 6. **Browser extension token rotation (`apps/extension/src/state.ts:8-13,44-49`):** As a defense-in-depth protocol enhancement on `/api/extension/*`, pair a short-lived access token kept only in memory-backed `chrome.storage.session` with a rotating refresh token (with reuse detection), rather than keeping a single long-lived bearer token in disk-backed `chrome.storage.local`.

### SEC-07 (`P2`, `line:platform`) - AI budget meter concurrency overshoot and post-call `record()` failure residual

- **Evidence:** `packages/agent/src/meter.ts:218` checks `meter.admit(call)` before invoking the model and calls `meter.record(call, usage)` afterward, intentionally catching and logging `record()` errors so a completed model answer is not thrown away. Two residual behaviors follow: (a) `apps/kernel/src/ai-meter.ts:44` evaluates `expected` projected cost on the member-Vy path only (and ignores `expected` on standard org calls) without taking an atomic DB reservation, so concurrent calls admitted near 100% of an org, module or agent budget can all complete and overshoot the cap, and (b) a transient database error during `record()` leaves that call's provider spend unrecorded in `org_usage`.
- **Recommendation:** Evaluate projected `expected` cost across all meter paths, add an optional atomic DB reservation/settle step when strict hard-cap enforcement is required for expensive calls, and retry or outbox-buffer failed `meter.record()` writes in `apps/kernel/src/ai-meter.ts` with an operational alert if recording still fails.

### AI-01 (`P1`, `line:platform`) - Hardening MCP cross-tool prompt-injection blast radius in `#3858`

- **Current baseline:** MCP write execution already enters a sealed `tainted: true` context (`packages/kernel-runtime/src/runtime.ts:2282`), and at `9a9f1cdfc` the sole MCP write (`social.mcp.draft_create`) creates an unpublished draft only (`#3932` amends ADR-0051 first; runtime code follows in `#3858` slices b-d).
- **New risk as `#3858` lands:** Once one MCP grant can read untrusted external content (customer conversation messages, public booking contacts with `sourceTrust: 'external'`, supplier invoice lines, meeting action items) **and** invoke per-line R1 commands directly (`ludy.engage.write`, `ludy.ads.draft`) plus R2/R3 proposals, indirect prompt injection inside external text can steer the connected LLM client to execute unintended R1 writes or flood deceptive proposals.
- **Deterministic controls (preserving unconditional `tainted: true` on all MCP inputs):**
  1. **Keep every MCP write/proposal unconditionally `tainted: true` and keep any external-facing or link-carrying mutation at R2+ (proposal-only):** When lines declare `CommandDef.mcp` under `#3858`, never expose a command as R1 if its fields can carry outbound messages, external URLs, money, account numbers or destructive state changes; R1 over MCP should stay restricted to narrow internal classifications/drafts.
  2. **Structured provenance on MCP read outputs and Ludy approval cards:** Expose `sourceTrust` and `tainted` flags consistently on MCP read schemas (as `ludy_parties_list` and `ludy_social_posts_list` already do) alongside supplementary control-character/boundary-tag scrubbing, and render the MCP `clientName` + grant provenance prominently on every MCP-originated proposal card in Ludy's Inbox and Home approval queue.
  3. **DB-backed per-grant R1-write and open-proposal caps:** Extend `DraftBudget` (`apps/kernel/src/mcp-endpoint.ts:945`) into a PostgreSQL-backed per-grant rate limit and maximum pending-proposals cap so a hijacked or looping agent cannot flood human approvers.

### AI-03 (`P2`, `line:platform`, `line:frontend`) - Progressive feedback for interactive coworker calls and provider-aware prompt caching

- **Evidence:** Interactive model calls where a user waits in the UI (such as `sign.field_propose` and `sign.clause_summary` configured with `SIGN_AI_TIMEOUT_MS = 25_000` at `packages/agent/src/sign-ai.ts:11`, `meetings.summary`, `meetings.chapters`, `meetings.ask`, `projects.tasks_from_source`, `hr.recruiting_brief`) await full `generateText` completion before returning.

### AI-04 (`P2`, `line:platform`) - Typo-tolerant Vietnamese search (`pg_trgm` over `search_fold` on non-hot tables)

- **Evidence:** `supabase/migrations/20261023060000_crove_finance_search.sql:9-45` and `20261226000000_crove_meetings_search.sql:7` use `to_tsvector('pg_catalog.simple', crove_kernel.search_fold(text))` without `pg_trgm`. `'simple'` FTS matches exact folded tokens and prefixes, but misses 1-character typos and infix substrings on party names, goods/services, or document codes (`pg_trgm` handles character similarity and substrings, not semantic synonyms; static screen synonyms in `Ctrl/Cmd+K` remain a client dictionary fix per `app-ux-2026-11-17.md` `SH-7`).
- **Recommendation:** Enable PostgreSQL's built-in `pg_trgm` extension (included in both `postgres:17` and `supabase/postgres:17`, zero external dependency) in a dedicated non-public schema and add GIN trigram indexes on `search_fold(...)` **only on non-hot tenant tables** (`party`, stock items), because `AGENTS.md`'s `-- crove:concurrent-index` rule on hot tables permits `pg_catalog` objects only. Because `@@` and trigram `%` operators are not `LEAKPROOF`, preserve the reader-checked `SECURITY DEFINER` id-filter pattern plus caller re-read under RLS for reader-scoped tables (`20261226000000_crove_meetings_search.sql:12,29`), and keep semantic/vector indexing over private notes and meetings closed per [ADR-0051](../adr/0051-vys-brain-is-a-dos-claw-agent-ludy-is-the-gate.md) `Q3`.

### MOD-01 (`P1`, `line:frontend`) - Route-level code splitting and initial bundle budget for `apps/app`

- **Evidence:** `apps/app/src/router.tsx:13-118` contains **85 static imports from `./routes/*` (96 `*Page` symbols)** across all 9 product modules (`Finance`, `Social`, `Ads`, `CRM`, `HR`, `Meetings`, `Projects`, `Notes`, `eSign`, plus all 10 `Settings` tabs). An external signer opening `/-/sign#<token>` or a solo founder using one app downloads and parses the route tree of every module on cold load.
- **Recommendation:** Measure the current production entry chunk and transitive chunk graph (`pnpm --filter @crove/app build`), convert module routes under `/o/$slug/*` and standalone public routes (`/-/sign`, `/-/sign-direct`, `/-/quote`, `/-/review`, `/-/report`, `/-/b/$org/$type`) to TanStack Router `lazyRouteComponent` while keeping `defaultPreload: 'intent'` (`router.tsx:745`), and enforce an initial JS gzip budget in `.github/workflows/ci.yml` (`static` job).

### MOD-02 (`P1`, `line:platform`) - Graceful shutdown double-signal race and container stop window

- **Evidence:**
  1. `apps/kernel/src/main.ts:134-139` registers `SIGTERM` and `SIGINT` handlers that call `shutdown()` without memoizing an in-flight promise, while `apps/kernel/src/kernel.ts:720-722` empties `stops.splice(0).reverse()` on the first call. A second signal arriving while `stop()` is draining `pg-boss` sees an empty `stops` list and immediately executes `process.exit(0)`, cutting off in-flight jobs and `flushOpsAlerts`.
  2. Worker shutdown (`apps/kernel/src/worker.ts:3222-3226` + `kernel.ts:699`) budgets up to `10s` (`boss.stop`) + `5s` (`lastBeat`) + `5s` (`flushOpsAlerts`), plus `pool.end()` and any active API upload/request drain (note: Node 26 `server.close()` already closes idle keep-alive sockets automatically). Meanwhile `docker-compose.yml` and `tools/deploy/compose.pilot.yml` leave Docker's default `10s` `stop_grace_period`, causing `SIGKILL` before drain completes.
- **Recommendation:** Cache `let stopping: Promise<void> | null = null` in `apps/kernel/src/main.ts:134` so duplicate signals await the running drain, bound `pool.end()` wait time on shutdown, and set `stop_grace_period: 35s` on `crove`, `api`, and `worker` in `docker-compose.yml` and `tools/deploy/compose.pilot.yml`.

### MOD-03 (`P2`, `line:platform`, `line:meetings`) - PostgreSQL RLS `InitPlan` hygiene, `PgBoss` pool ceiling and partitioning triggers

- **Evidence:**
  1. **Uncached `STABLE` context helpers in `meetings` RLS policies:** `supabase/migrations/20270115200000_crove_meetings_mcp_company_read_tighten.sql:53` (the latest `meeting_read` definition, which includes the `mcp_company` branch), `20261124130000_crove_meetings_core.sql:257,272,290` (`meeting_insert`, `meeting_update`, `meeting_delete`), and `20261231010000_crove_meetings_translation.sql:51-65` (`translation_read`, `translation_insert`, `translation_delete`) invoke `crove_kernel.ctx_actor_type()` or `crove_kernel.ctx_user_id()` directly rather than `(SELECT crove_kernel.ctx_actor_type())`, preventing PostgreSQL from hoisting the GUC read into a once-per-scan `InitPlan`. Ship a forward migration preserving the exact `20270115200000` `mcp_company` logic while wrapping bare `ctx_*()` calls in `(SELECT ...)`, and add a `CREATE POLICY` check in `tools/ci/migration-lint.mjs`.
  2. **Worker connection ceiling (`apps/kernel/src/worker.ts:790`):** `new PgBoss({ connectionString: deps.connectionString, ... })` uses `pg-boss`'s default `max: 10` pool alongside `workerPool` (`WORKER_DATABASE_POOL_MAX`, default 10) and `crove-relay-listen` (a default theoretical ceiling of 21 connections per worker process). Configure an explicit `max` on `PgBoss` derived from worker settings and document the total budget in `.env.example`.
  3. **Append-only table partitioning trigger (Cloud scale):** When multi-org Cloud volume on append-only tables (`crove_kernel.outbox_event`, `crove_kernel.mcp_call_audit`; note `refusal_tally` is an upsert counter table, not append-only) makes retention `DELETE` sweeps expensive, adopt monthly `PARTITION BY RANGE` with composite keys and `org_purge` compatibility verified by an ADR first.

### MOD-04 (`P2`, `line:platform`) - Supply-chain automation gates, `pnpm` bootstrap and request-to-job trace IDs

- **Evidence:**
  1. **`pnpm` bootstrap parity:** `Dockerfile:9`, `apps/extract/Dockerfile:11`, `apps/media/Dockerfile:14`, `apps/web/Dockerfile:10` (cached when base layers hit) and `.github/workflows/*.yml` (fresh CI runners) install `pnpm@10.34.7` to download `pnpm@12.11.2` (`package.json:7`). Installing `pnpm@12.11.2` directly from a SHA-256-verified tarball (matching `gitleaks.yml:29-33`) removes an unverified registry fetch on cold builds.
  2. **Automated checks backing `renovate.json` automerge (`renovate.json:14-22`):** GitHub's default `CodeQL` setup already scans `actions` and `javascript-typescript` on PRs. Complement it with GitHub `dependency-review` (enforcing AGPL-3.0-compatible licenses and blocking high/critical GHSA advisories), container image CVE scanning (`trivy` / `grype` covering `ffmpeg` in `crove-media`), and `actions/attest-build-provenance` in `deploy.yml:174-184` (aligned with `docs/plan/crove-os-kernel.md` and `ADR-0001`).   3. **Staged-mode pre-commit checks (`.githooks/pre-commit`):** `tools/ci/spdx-header.mjs` currently reads `HEAD` blobs and `tools/ci/pii-scan.mjs` reads working-tree files (`git ls-files`).
